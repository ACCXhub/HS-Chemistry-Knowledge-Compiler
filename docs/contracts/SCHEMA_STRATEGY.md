# Schema Strategy

Status: **F1 canonical strategy; field-level schemas deferred to F2**

## 1. Authoring principles

Canonical source must be:

- human-reviewable;
- diff-friendly;
- auditable;
- schema-validatable;
- deterministic to compile;
- independent of any particular database/runtime.

## 2. Prefer embedded values where lifecycle does not require identity

Composition, context, reaction participants, reaction conditions, teaching path nodes, and ordinary bonds are embedded by default.

Do not normalize values into top-level UUID records merely to make graph export convenient. Graph/database projections can be generated by the compiler.

## 3. Validation layers

F2 schemas should support:

1. syntax/schema validation;
2. stable-ID/reference validation;
3. controlled-vocabulary validation;
4. cross-record semantic validation;
5. chemistry-specific validation;
6. deterministic canonical serialization.

## 4. File layout

File/directory layout is an authoring concern and never identity-bearing. Source may be sharded by reviewability/ownership while references remain stable.

## 5. Generated artifacts

External artifact schema/versioning is contract-owned. Internal compiler plan/index layout is not part of source schema compatibility.

## 6. Language neutrality

Canonical schemas and rule contracts must not expose Python/SymPy/Rust/C++ implementation types as semantic requirements.
