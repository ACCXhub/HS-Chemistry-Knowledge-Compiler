# Schema Strategy

Status: **F2 executable source/schema strategy**

## 1. Authoring principles

Canonical source must be:

- human-reviewable;
- diff-friendly;
- auditable;
- schema-validatable;
- deterministic to compile;
- independent of any particular database/runtime.

F2 uses YAML for authored source and JSON Schema Draft 2020-12 for structural validation.

## 2. Prefer embedded values where lifecycle does not require identity

Composition, context, reaction participants, reaction conditions, teaching path nodes, and ordinary bonds are embedded by default.

Do not normalize values into top-level UUID records merely to make graph export convenient. Graph/database projections can be generated by the compiler.

F2 keeps phase on reaction/request participants and product templates; phase does not become chemical identity.

## 3. Executable F2 schemas

The F2 vertical slice owns only the schemas it actually exercises:

- `schemas/f2-record.schema.json` — Entity, Reaction/ReactionForm, Rule, Source, and Evidence shapes used by the slice;
- `schemas/f2-case.schema.json` — deterministic audit/example requests.

These schemas intentionally do not claim to freeze every future chemistry concept.

Validation order is:

1. safe YAML parsing with duplicate-key rejection;
2. JSON Schema validation;
3. stable-ID uniqueness/reference validation;
4. entity-kind / participant-kind semantic validation;
5. rule compilation/type checks;
6. chemistry-specific balancing/conservation validation during inference.

Malformed source is rejected rather than repaired.

## 4. File layout

F2 authored source is split by current ownership only where needed:

```text
knowledge/domain/f2_entities.yaml
knowledge/domain/f2_reactions.yaml
knowledge/rules/f2_rules.yaml
knowledge/fixtures/f2_cases.yaml
```

File/directory layout and traversal order are not identity-bearing. The compiler sorts source records by stable semantic coordinates before source hashing.

## 5. Deterministic serialization

F2 canonical semantic encoding is canonical JSON as recorded in `ADR-F2-001`:

- UTF-8;
- NFC Unicode normalization;
- lexicographically sorted mapping keys;
- compact JSON separators;
- integer-only semantic numeric domain;
- no timestamps, local paths, process IDs, or traversal-order metadata.

The same canonicalization is used for source semantic digests and `candidate_key`. Exact emitted artifact bytes are hashed separately for the manifest.

## 6. Generated artifacts

External artifact schema/versioning is contract-owned. F2 emits deterministic JSON artifacts under caller-selected build output (normally `build/**`, ignored by Git):

- `manifest.json`;
- `reaction-candidates.json` for audit mode;
- `compiled-rule-plans.json` for compile mode;
- `diagnostics.json`.

Generated artifacts are reproducible outputs and never become editable source truth.

Internal `RulePlan`, indexes, and evaluator data layout remain Compiler-owned implementation details.

## 7. Language neutrality

Canonical schemas and rule contracts do not expose Python implementation types as semantic requirements. Python is the F2 reference implementation only.
